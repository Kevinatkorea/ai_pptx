## L001 — selfcheck의 검증 정규식은 출력 형태를 좁게 가정하지 말 것
**발생**: 2026-05-30, `selfcheck/run_transform_demo.py` 첫 실행.
**증상**: transform 코드는 정상이고 도형도 옳게 생성됐는데, y 좌표 검증만 실패.
**원인**: 검증 패턴이 `name="year_box_0"[^/]*?/></p:nvSpPr><p:spPr>...` 처럼 OOXML 출력의 정확한 형태(자식 요소 한 개)를 가정. 실제 출력은 `<p:cNvPr.../><p:cNvSpPr.../><p:nvPr/>...` 로 자식 여러 개.
**교훈**:
- 검증 정규식은 **무엇을 확인하는지의 본질**만 표현하고, 사이의 OOXML 구조는 `.*?` + `re.S` 로 둘 것.
- 좋은 예: `rf'name="year_box_{i}".*?<a:off x="\d+" y="(\d+)"'` (재시 0).
- 나쁜 예: 구조 전체를 직렬화한 `</p:nvSpPr><p:spPr><a:xfrm>...` (한 글자만 달라도 깨짐).
- **본말 전도 방지**: 테스트 실패 시 먼저 "코드 출력의 실제 형태"를 출력해서 보고 패턴을 고치자. 코드부터 의심하지 말 것.
